## Fix before accepting the vertical slice

1. **HUD labels are placed off-screen, not mysteriously failing to render.** `Assets/Game/Editor/Level1SceneSetup.cs:184` creates height/HP labels centered at x=-350/+350, while `AddText` at line 273 makes each rectangle 1000 units wide with centered anchors/pivot. In a 1080-wide canvas the height text starts at screen x=-310; the right-aligned HP text ends at x=1390. Their short strings fall outside the viewport. The pause button also extends to x=1110. Use actual top-left/top-right anchors, matching pivots, reasonable widths and safe-area margins; separate HP from Pause. Fix the scene builder and regenerate through Unity. Do not spend another build investigating fonts or bindings. Verify both 1080×2520 and the 1080×1920 reference aspect.

2. **POST requests containing a body can wait for the socket timeout.** In `Assets/Game/Webhook/BumpListener.cs:200`, the header read can consume headers and body together, but bytes after the header terminator are discarded. `ReadBody` then tries to read the complete body again. A normal coalesced POST can wait roughly three seconds, violating the immediate-event requirement. Preserve already-read body bytes and read only the remainder. Reject malformed/oversized lengths and incomplete bodies rather than silently accepting them after a timeout. Add focused transport regression cases for a coalesced header/body, fragmented delivery and an incomplete body. The documented empty POST smoke test does not cover this bug. This finding is from source inspection, not a new timing measurement.

3. **Successful HTTP responses can correspond to no dispatched effect.** `BumpListener.cs:178` returns `200 accepted:true` before `GameSession.cs:71` validates the queued request. A pause/menu/retry transition can therefore discard a successful request. Make main-thread acceptance authoritative, with a bounded wait on the network worker and a non-success response for rejected/expired requests; never block the Unity thread. Preserve stale-level rejection. Also reserve queue capacity atomically: the current capacity check, enqueue and count increment are separate operations across concurrent client workers. Verify rapid requests and state transitions. This closes an explicit plan contract; no networking framework is needed.

4. **The glove effect misses the character and is silent.** `GloveBurstView.cs:136` converges on canvas origin, while the camera frames the character below center. `Level1SceneSetup.cs:246` creates an AudioSource without assigning a clip. Convert the character's on-screen hit position to canvas coordinates for the glove target, keep the large screen-spanning entrances, and wire the existing licensed impact clip. Verify the visible impact, audible sound and subsequent climbing together. The saved screenshot proves an effect exists; it does not prove impact alignment, audio or recovery.

5. **The device screenshots contain runtime errors.** Both `evidence/g2_playing_v2.png` and `evidence/g2_glove_burst2.png` show `Can't add component because class 'CapsuleCollider' doesn't exist!`. Investigate the runtime `CreatePrimitive(Cylinder)` in `HazardBand.cs:39`; stripping of components used only through runtime primitive creation is a likely cause, not yet independently reproduced here. Prefer a serialized visual prefab with the required mesh/material and no unwanted collider, or explicitly retain the required component if keeping runtime primitives. Verify a clean development-build log; hiding the console is not a fix.

6. **The gate's completion/recovery evidence is still missing.** After the fixes, record a short device check covering menu → start → climb → hit/recovery → summit → menu; lose → retry with reset state; pause/resume; real GET and POST → effect → resumed climbing → completion.
